# 模型与工作流选择

本文件用于选择候选技术路线，不替代上游 README、模型卡和许可证。具体版本、权重、量化和硬件要求在执行前必须重新核验。

## 先按任务分类

| 任务 | 优先确认 | 常见路线 |
|---|---|---|
| 文生视频 | 画面可控性、动作幅度、镜头时长、文字需求 | Wan2.2、LTX、HunyuanVideo、CogVideo |
| 图生视频 | 参考图质量、主体必须保持的特征、镜头运动 | 支持 I2V 的当前官方模型或 ComfyUI 工作流 |
| 视频重绘 | 是否保留动作、构图、身份、时长和音频 | 支持 V2V/控制条件的管线 |
| 视频续写 | 首尾衔接、主体漂移容忍度、累计误差 | 原生扩展能力或分镜生成后剪辑 |
| 多镜头短片 | 剧本、镜头表、角色设定、声音和字幕 | 多模型组合 + 剪辑流程 |
| 研究/训练 | 数据、算力、分布式环境、评测方案 | Open-Sora、Diffusers 或模型官方训练代码 |
| 服务化/批处理 | API、队列、缓存、失败重试、日志 | Diffusers 脚本或 ComfyUI API |

## 候选路线

### ComfyUI

**适合：**

- 需要节点式搭建、复用和调试工作流。
- 需要把模型、控制条件、LoRA、超分、补帧和编码串起来。
- 需要通过 API 调用已经验证的工作流。

**执行前检查：**

- ComfyUI 版本。
- 工作流 JSON 所需的全部自定义节点及版本。
- 模型、VAE、文本编码器和 LoRA 的目录。
- 自定义节点代码来源与许可证。

### Wan2.2

**适合：**

- 需要 Wan 官方公开的 T2V、I2V 或其他任务能力。
- 需要中文生态、ModelScope 下载路径或官方 Wan Skills 作为参考。

**执行前检查：**

- 当前官方仓库列出的模型名称和任务。
- 具体模型权重的许可证与输入规格。
- 当前推理脚本或 ComfyUI 支持方式。

### LTX-Video / LTX-2

**适合：**

- 需要 LTX 当前上游提供的视频生成、关键帧、扩展或音视频能力。
- 需要使用官方 ComfyUI 集成或 Python 推理。

**执行前检查：**

- 当前主仓库指向的推荐模型和文档。
- 音频、关键帧、扩展等能力是否属于所选具体模型。
- 所需依赖、精度和硬件条件。

### HunyuanVideo / HunyuanVideo-1.5

**适合：**

- 需要腾讯混元视频官方路线。
- 需要在基础模型与较轻量路线之间比较。

**执行前检查：**

- 使用的是基础仓库、1.5 还是其他官方衍生项目。
- 代码许可证、权重条款和地域/商业条件。
- 当前支持的输入模式与推理配置。

### CogVideo

**适合：**

- 需要 CogVideo 系列。
- 需要 Diffusers 或 Python 管线集成。

**执行前检查：**

- 具体模型分支与模型卡。
- 分辨率、帧数、输入模式和依赖版本。
- 许可证是否满足目标用途。

### Open-Sora

**适合：**

- 训练、评测、研究或定制完整视频生成管线。
- 有明确的数据、算力和工程环境。

**不应默认用于：**

- 用户只想快速在普通电脑上制作一条短视频。

### Diffusers

**适合：**

- 需要 Python 自动化、批处理、测试或服务化。
- 需要把视频模型与调度器、编码器、VAE 或其他组件组合。

**执行前检查：**

- 当前版本是否包含目标模型对应的 pipeline。
- 模型示例所要求的 PyTorch、Transformers、Accelerate 等版本。

## 硬件路由原则

不要只根据“显存有多少”作结论。还要确认：

- 模型参数规模、精度和量化方式。
- 帧数、分辨率、批量和控制条件数量。
- 文本编码器、VAE 和多个模型是否同时驻留显存。
- CPU 内存、磁盘空间、PCIe 传输和 offload 成本。
- GPU 架构对 dtype、Flash Attention 或特定内核的支持。

### 保守的处理顺序

1. 选择上游明确支持的较小模型或低精度方案。
2. 用 2–5 秒的最小样片实测峰值显存。
3. 先降低帧数和分辨率，再降低批量。
4. 仅在管线支持时启用 CPU offload、分块或量化。
5. 最后再增加控制节点、LoRA、超分和补帧。
